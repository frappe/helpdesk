## 2. How it was used

The agent did not only answer questions. It worked directly on the team's
machine and repository:

- read the brief and the Helpdesk and Frappe source code;
- ran commands in WSL (install, bench, test runners, SonarQube, k6, ZAP,
  pip-audit, Playwright, Cosmic Ray) and read their output;
- wrote and edited files: tests, scripts, configuration, reports and the
  management documents;
- on GitHub, through the member's signed-in `gh` account (`ibbster05`):
  created the 35 Issues, opened PRs #1 and #37–#44, merged all of them
  except #37 (closed unmerged), closed Issues #2, #3, #4, #15, #21 and #27, and set
  branch protection on `team/sqe-tests`;
- queried the public OSV vulnerability database (package name and version
  only) to check the DOMPurify advisories for DEF-14.

One product decision was put to the team rather than made by the agent:
the assignment rule for DEF-03 ("agents only", chosen 18 Nov, even though
it makes one upstream test fail).

What the team did itself, according to the prompts and the session:

- chose the repository and approved the scope ("Approve, start tests");
- chose the order of the activities (each short prompt in `PROMPTS.md`);
- created the WSL user, the GitHub fork and the `gh` sign-in;
- ran the three area commits and the first push from the agent's
  step-by-step instructions.

**Extent.** In plain terms, the code, tests, configuration, reports and
documents in `tests/team/`, the workflow in `.github/workflows/sqe-quality-gate.yml`
and the DEF-01 fix in `hd_ticket.py` were produced by the agent. The commits
carry a member's name, but their content was generated by the agent. The
team's responsibility is to check this work and to be able to explain all of
it in the viva (brief, section 7).

## 3. Rules the agent followed

- **Evidence from real runs only.** Every number in the reports comes from a
  run on this machine or a GitHub Actions run, with the raw output kept in
  `*/evidence/`, `reports/` or the Actions log. No screenshot, report or run
  was edited.
- **Actual effort not invented.** The Actual column in `ESTIMATION.md` is
  empty; members fill it from their own time logs.
- **Synthetic data only.** Test accounts are `@sqe.test`; their passwords are
  generated into the git-ignored `.env` and were never printed. The SonarQube
  admin password and token stay in `~/.sqe-env`.
- **Claims checked against source.** Statements about Frappe or Helpdesk
  behaviour cite the file and line they were checked in. Where something was
  not verified, the document says so (for example "not yet analysed" for
  DEF-06/07/08, and "not tested" for sending a message on the stale page in
  DEF-35).
